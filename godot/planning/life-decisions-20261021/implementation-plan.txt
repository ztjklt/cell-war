细胞战争：小脑生活决策、身体机能与长局生存计划
日期：2026-10-21
状态：原始设计及后续范围。2026-10-21 已按用户新要求接入 40 个事件、120 个选项和机能机制；实际交付与验收见 implementation-status.txt，多病原与药品助手仍待后续。

一、用户本轮明确的方向
1. 沿用左上角现有的小脑形象，在它下方通过对话提出外部生活选择。
2. 选择包含熬夜、加班、吃饭、垃圾食品等，并扩展更多日常情境。
3. 选择影响两个主要数值：金钱、身体机能。“机轮值”暂按“身体机能值”理解，名称可调整。
4. 金钱后续用于购买药品；药品注入身体后作为细胞的助手，配有独立动态形象。
5. 身体机能越低，入侵发生概率、病原数量、种类和应对复杂度总体越高。
6. 一局是可跨多次游玩的长局，以人体最终存活多久作为主要成绩。
以下节奏、数值、年龄、死亡缓冲和具体选项效果均为建议，属于后续联调参数。

二、现有工程与接入位置
1. scripts/advisor_dialogue.gd 已有小脑命中区域、三话题按钮、分句对话、主动提醒和表情联动。
   对话历史和显示状态目前主要保存在 UI 内，不能直接作为长局决策的权威状态。
2. scripts/advisor_rules.gd 提供人体情况、守卫建议和援军补给的固定规则回复。
   非战役分支目前统一使用沙盒文案，新的长局需要独立的身体状况和风险说明。
3. scripts/influenza_colonies.gd 已能在 fullbody 的认证组织落点开启流感群落。
   全身地图首次运行目前固定启动右肺感染；start_outbreak 的批次数量限制为 10–20。
   现有施工、孵化、关口作战和清除状态应继续复用。
4. data/infection_zones.json 登记了 12 个器官的 56 个小地板落点。
   落点资源的存在不代表任何病原都能在该器官生成；事件须另有病原与入口规则。
5. scripts/scenarios.gd 已负责既有战役波次、循环防线和关口扩散。
6. scripts/simulation.gd 有固定模拟步进、暂停和状态快照；scripts/save_game.gd 有本地原子写入与校验。
7. 当前没有全局金钱、身体机能、生活决策调度、人体寿命结算或药品助手经济闭环。
8. 当前首页“开始作战”进入循环防线，不能误认为已经存在长期人体生存入口。
9. 既有感染区域规划中的红白细胞联合净化要求继续保留，未实现的部分按原规划单独验收。

三、核心循环与职责
生活时间推进 -> 小脑提出情境 -> 玩家作选择 -> 立即与延后结算 ->
金钱和身体机能变化 -> 接触风险与入侵调度 -> 合法感染落点 ->
细胞防守、控制扩散、建设与补给 -> 感染负担改变机能 -> 下一轮生活选择。
药品开放后：金钱 -> 购买 -> 库存 -> 注入 -> 有持续时间和职责的助手 -> 帮助细胞控制感染。

小脑是人体与外界之间的联络员：提出问题、解释代价、汇报后果、提醒风险。
正式决策由玩家点击选项完成。首版使用本地情境表和规则组合，不依赖网络或运行时大模型。
身体机能主要管理人体的整体承受与恢复能力、外部感染风险，不直接改写所有细胞的原有战斗数值。
细胞依然承担战术操作；钱不会自动替代地图里的葡萄糖、氧气或生产资源。

四、两个主要数值与人体状态
1. 金钱：非负，建议首轮从 300 开始，作为抽象游戏货币。
   收入来自正常工作与额外机会；开支来自生活、休整及未来的药品。
   收入和生活支出按生活周期结算，不允许每次点对话重复领钱。
   正常工作扣除基本生活开支后应有小额结余，额外加班不是唯一资金来源。
   选择长期休息可减少收入；低余额时保留免费恢复和基本生活方案。
   首版不做贷款、债务利息或因余额归零立即判负。
2. 身体机能：0–100，建议开局 85。
   休息和良好生活习惯提供逐步恢复；透支、持续感染和年龄压力产生损耗。
   短期变化和持续变化分开：例如连续加班可能先收入增加，随后数个周期恢复变慢。
   单个普通生活选择建议只影响约 1–6 点，避免一顿饭决定数十年寿命。
   小脑能说明最近的主要变动来源，例如“休整 +3、感染负担 -2”。
3. 后台状态只保留会改变玩法的记录：年龄、连续熬夜次数、正在感染的区域与严重度、
   有限期的暴露风险、恢复效果、危急倒计时、决策历史与已安排事件。
   它们不增加一排需要玩家管理的全局数值条。
4. 默认不额外加入随机职业、遗传或开局体质差异，以便比较不同策略。

五、小脑对话与选择交互
1. 保留现有小脑形象、表情和分句说话方式。新情境在小脑下方展开。
2. 每次只展示一个需要回答的生活决策；每个决策提供 2–3 个能读懂的选择。
3. 显示内容：一句情境、2–3 个按钮、即时金钱/机能变化、持续时间与风险方向。
   不把隐藏概率包装成必然结果；区分“机能 -3”和“未来一段时间呼吸道暴露风险上升”。
4. 示例：
   小脑：“今晚项目赶进度，要继续加班吗？”
   A. 准时下班：本次额外收入 +0，机能逐步恢复 +2。
   B. 加班一会儿：金钱 +60，机能 -3。
   C. 通宵赶工：金钱 +140，机能 -6，接下来两个生活周期恢复较慢。
   以上只是抽象游戏联调值，工资和支出要在同一周期预算中一起校准。
5. 有待决策时，显示简短提示；玩家可以主动展开详细内容。
   展开选项时默认暂停模拟，提交后恢复先前暂停状态；原来就在暂停则保持暂停。
   收起选项不会默认替玩家作决定，也不会把选项视作放弃。
6. 待处理时最多保留一个生活决策，不生成过期问卷；未选时战斗可在手动恢复后继续。
   危险暴露一旦已由先前选择产生，其延后后果仍正常推进，不因收起新对话而取消。
7. 决策结算、入侵告警、日常闲聊使用明确优先级；普通汇报不得覆盖未提交的选择。
8. 确认后给一句结果反馈，并更新两项数值。UI 防止双击、重复快捷键或读档重复发奖。
9. 手机竖屏按钮纵向排布、可滚动，展开时挡住对应地图输入；点击选项不向地图下令。
10. “人体情况”话题显示全局机能、当前感染、最近生活影响和恢复建议。
    保留“守卫建议”，药品开放后增加药品/助手入口；不挤掉既有战役功能。

六、首批 40 个生活情境候选
以下是内容库，先制作其中 12–16 个形成闭环，再扩展；箭头表示方向，具体数值统一配置。
每个情境均须同时写明金钱和机能效果，允许其中一项为 0，不能强行让每次选择都扣两项。

作息与休整
01. 今晚赶工：准时休息 / 适度加班 / 通宵；收入和透支逐级增加。
02. 周末接单：全天休息 / 半天兼职 / 连续接单；换取收入但占用恢复时间。
03. 深夜娱乐：按时结束 / 再玩一会儿 / 玩到天亮；无工资收益，满足叙事和后续情境分支。
04. 连续熬夜后的早晨：请假恢复 / 正常工作 / 继续硬撑；与熬夜历史联动。
05. 午间安排：短暂休息 / 外出办事 / 利用午休加活；小额收入与恢复机会取舍。

工作与收入
06. 临时奖金项目：拒绝 / 分担一部分 / 全部接下；收益提高，连续工作代价递增。
07. 同事请求换班：保留休息 / 换一次 / 连换数班；产生后续补休或感谢事件。
08. 出差机会：留在本地 / 普通出差 / 高补贴长途；收入与旅途暴露窗口不同。
09. 稳定岗位与高压项目：稳定安排 / 短期高薪任务；提供持续数周期的收入、恢复差异。
10. 身体不适时交付：休息延期 / 降低工作量 / 强行完成；只在低机能或感染期出现。

饮食与花费
11. 午饭怎么吃：正常一餐 / 便宜快餐 / 暂时不吃；花费、短期恢复和后续饥饿情境不同。
12. 深夜外卖：简单夜宵 / 重口味外卖 / 不点单先休息；与当天是否用餐、熬夜联动。
13. 周末备餐：花时间准备 / 买现成餐 / 连续省略正餐；金钱与后续恢复效率取舍。
14. 路边摊邀请：换一家 / 正常购买 / 选择高风险食物；使用游戏化消化道暴露标签。
15. 促销零食囤货：不买 / 少量 / 大量；先花钱，后续多次饮食情境改变，而非立即感染。

活动与通勤
16. 通勤选择：步行一段 / 公交 / 打车；花费、时间和接触窗口不同。
17. 晚间活动：轻度活动 / 休息 / 超负荷训练；低机能时调整选项和结果。
18. 久坐工作：定时活动 / 赶进度不动；当前收益与持续恢复差异。
19. 休假安排：低成本休整 / 花钱度假 / 接活赚钱；三条可行路线。
20. 恢复期间出行：取消 / 缩短行程 / 完整行程；根据正在恢复的状态改变后果。

社交与外界接触
21. 拥挤聚会：不参加 / 短暂参加 / 通宵聚会；叠加接触和作息风险。
22. 同事出现不适：减少接触 / 正常接触 / 主动代班；不同暴露和工作结果。
23. 换季出行：调整安排 / 按原计划 / 连续奔波；使用当前生活阶段和事件冷却。
24. 突发天气：更换通勤 / 临时等候 / 强行赶路；影响开支、休整，天气本身不直接生成病原。
25. 旅行返程：先恢复 / 直接上班 / 紧接下一段行程；可能接续差旅事件。

压力与生活安排
26. 一周排期过满：取消部分 / 保持安排 / 继续增加任务；影响未来数周期。
27. 朋友邀约：低成本短聚 / 高消费聚会 / 留在家中；不把全部社交固定设为有害。
28. 额外进修：适度安排 / 压缩睡眠突击 / 暂缓；延后收入机会与眼前透支。
29. 家庭事务：请假处理 / 分担 / 连续挤占休息；剧情分支不增加新的全局好感数值。
30. 长假后的节奏：循序恢复 / 立即满负荷；影响数周期恢复和收入。

预算与恢复
31. 本周预算紧张：保留基本饮食 / 缩减娱乐 / 同时透支工作；保留免费可行路线。
32. 拿到额外收入：存钱 / 改善近期生活 / 预留后续药品预算；不是必须立刻消费。
33. 低机能恢复窗口：低成本休息 / 花钱安排更充分的休整 / 继续工作。
34. 预防性准备：维持现状 / 支出换取一段时间较低的接触风险；不等同零感染概率。
35. 药品不足时：继续防守 / 使用已有库存 / 购买已解锁助手；药品阶段才启用。

连续事件与后果
36. 连续加班后获得补休：兑现补休 / 换奖金；让先前选择产生可读的后续机会。
37. 接触风险后的观察期：减少活动 / 正常安排；不会提前告诉玩家隐藏感染抽签结果。
38. 清除感染后的恢复：循序工作 / 花钱休整 / 立即冲刺；需要刚清除感染的历史条件。
39. 前期进修带来机会：接受短期项目 / 选择稳定增收 / 暂缓；不能无限刷新同一奖励。
40. 机能持续恶化警报：休整 / 使用已解锁助手并减负 / 冒险继续；明确显示危急后果。

情境生成规则：按年龄阶段、金钱、机能、最近感染与决策历史筛选，再按权重抽取。
同一情境有冷却；相邻不连续出同一类别。工作、饮食、恢复、接触等内容交替出现。
同一内容可有少量本地文案变体，但数值由固定选项配置确定。
无钱支付时禁用对应付费项并说明原因；每个事件至少有一个合法选项。
连锁情境先实现加班—补休、接触—观察、感染—恢复三条，控制内容维护成本。

七、从生活选择到“何时、何处、何种入侵”
1. 必须区分外部入侵与体内扩散。
   外部入侵由本模块调度；已存在病原突破关口后，由原有单位和路径逻辑传播。
   一个失守关口不会凭空在另一器官额外生成一批外部敌人。
2. 身体机能主要改变发生概率、批次数量分布和可选病原复杂度；
   暴露情境决定允许的入口/器官和病原池，年龄提供温和的长期压力。
   低机能本身不凭空制造某个特殊病原，也不让所有器官随机同时感染。
3. 首版只启用正式已接入的流感群落。呼吸道暴露映射到已有合法肺组织落点。
   消化道等暴露先记录为后续扩展，只有对应病原、落点和完整行为接入后才启用。
   如要模拟从鼻腔实际进入肺部，需另补全入口导航，不能以动画穿墙代替。
4. 调度先生成候选，依次检查：病原注册、暴露条件、事件冷却、机能权重、
   活跃感染预算、所属器官、合法小地板与实际出生空间。通过后才创建一次感染。
5. 建议的概率计算：r = base_rate(age) × (1 + 1.5 × q) × exposure_multiplier，
   q = clamp((100 - function) / 100, 0, 1)。
   r 的单位为“每模拟分钟的候选次数”；每步 p = 1 - exp(-r × dt / 60)。
   由此不依赖画面帧率；暂停不抽取，倍速只按模拟时间加速。
   base_rate、暴露持续期、冷却与全局预算共同联调，不能只凭公式声称平衡。
6. 候选数量仍遵守现有接口 10–20：
   机能 80–100：低发生率，偏向 10–12，单一基础病原。
   机能 60–79：发生率上升，偏向 10–16，基础病原为主。
   机能 30–59：更频繁，偏向 14–20，逐步开放已注册复杂病原。
   机能 0–29：高风险，偏向 18–20，可在预算内出现多处/混合威胁。
   档位之间连续插值，边界不突然增加数倍难度。
   要扩大单批超过 20，必须修改现有接口与施工/性能测试；不把配置改大当成已经生效。
7. 活跃感染设置上限；新外部事件预留独立预算，保留现有据点增殖的行为。
   首版建议上限 2 处，联调后才扩到 3–4 处；接近上限时延后新暴露事件。
   延后队列有容量和到期规则，不在战后瞬间倾倒积压的全部感染。
8. 出生拥堵时保留已确定的待投放记录并有限重试，不重新抽签领另一批。
   不能反复取消再抽到更方便的位置，也不能越界、贴关口或占用血管投影出生。
9. 入侵写入原因记录：对应生活事件、机能、暴露类别、候选时间、器官和批次ID。
   小脑汇报“近期接触增加了风险，右肺发现感染”，不将一次选择说成必然病因。
10. 新长局启用调度器后，关闭它的“首次固定右肺感染”。既有全身模式和测试保留原入口。
    第一场教学感染可由新长局显式安排一次并记录，不能叠加两个初始化器。

八、机能损耗、恢复与回旋空间
1. 机能变化集中结算：生活即时净变化 + 持续效果净变化 + 恢复 - 年龄损耗 - 感染损耗。
   恢复和损耗分别使用正值记录，最终按“增益减损耗”合计；同一来源不得在多个模块重复扣除。
2. 感染负担按活跃区域规模、持续时间、据点和扩散阶段计算；
   不按每颗病毒每帧扣血，也不因一个普通细胞阵亡直接扣一大块人体机能。
3. 每周期生活透支、感染和年龄损耗分别设上限，避免低机能增加感染后瞬间跌到零。
4. 休息的恢复逐步发生，避免一次点击把整条机能拉满。
   连续透支增加未来休整成本；停止透支并控制感染后仍可回升。
5. 清除感染减少负担并给恢复窗口，不直接“返还全部损失”。
   身体机能恢复不会自动删除地图里的敌人；细胞仍需作战与净化。
6. 无钱时保留较慢的免费恢复；不得出现钱少—只能加班—机能下降—只能买药的强制死循环。
7. 年龄逐步降低恢复上限/效率并提高基础压力，避免玩家只靠固定休息策略无限复原。
   初期先实现温和曲线，不增加额外隐藏寿命抽签或突然的必死年龄。

九、长局时间、死亡与成绩
1. 用新长局自己的 life_calendar，不复用沙盒的六分钟一天、季节与饥饿设定。
2. 建议普通模式从成年开始，例如 20 岁；1 游戏年约等于 6–10 分钟未暂停模拟时间。
   若生存至 70 岁，对应约 5–8.3 小时主动运行；早亡更短，守得更好可以更长。
   此为节奏目标，不保证某个年龄或强制结束时刻。
3. 用户修订：首次联系在 180 秒有效游玩后出现；之后每次回复后等待 120–180 秒有效游玩。
   暂停不计时，2 倍速不会缩短外部联系的实际间隔；未回复时不积压新事件。
   “今天要不要熬夜”是一个生活片段，并代表随后一段时间的习惯倾向；
   界面需说明时间经过，不把某一顿饭等价成损失一个季度寿命。
4. 生活日历、年龄、机能、冷却、药品时间、产兵与生存成绩统一跟随模拟时间。
   暂停和退出不推进；首版不做离线死亡。倍速不改变单位模拟时间的事件概率。
5. 人体机能降至 0 后进入明确危急状态，建议保留 30–60 秒模拟时间的最后抢救窗口。
   危急中恢复到安全阈值可脱险；持续无法恢复才结束。阈值和窗口集中配置。
   同时给出主要原因和剩余窗口，不能无提示结束一局长达数小时的游戏。
6. 单个器官失守或一队细胞死亡先提高感染/功能负担，不默认等于整个人立即死亡。
   既有战役的局部胜负继续使用原规则，新长局的人体死亡单独结算。
7. 主成绩为存活年龄，并显示本局实际经历的游戏年数；正常难度与不同时间倍率配置分开记录。
   辅助统计包括决策次数、总收入、药品支出、净化次数、最大同时感染数和死因摘要。
   暂停时间不计入存活时间，金钱和杀敌数不取代主要寿命成绩。
8. 结算存活时长、人体状态与关键历史；结算事务仅执行一次，读档不重复入账。

十、药品助手的后续接口与制作顺序
1. 首版先做钱、机能、生活选择与真实入侵，明确金钱现阶段能支付哪些生活选项。
   未开发的药品入口显示待开放或暂不展示，不给玩家一个可以花钱却没有作用的按钮。
2. 后续购买只改变金钱和库存，注入才消费库存并生成助手；无法生成时不吞库存。
3. 助手原型先按玩法职责命名：支援防守、协助运输、协助组织恢复、针对已注册病原的专门支援。
   先实现一个防守助手原型，再逐个扩展，不在本计划中暗定现实药品种类、用途或剂量。
4. 每个助手明确持续时间、生成位置、体积、寻路、作用对象、冷却、叠加上限和退场规则。
   若通过血流起效，应从已登记注入口进入并实际行进；未建立合法注入口前不伪装成完整注射表现。
5. 药品不能直接把人体机能充满或全身清屏；效果需通过已定义的助手行动或有限期效果兑现。
6. 助手保留用户要求的动态形象：角色设计后制作移动、工作/攻击、受击、退场等所需动作。
   素材生产与审阅另按现有规则执行；本轮不调用生图、视频或 3D 生成。
7. 库存、活跃助手、位置、生命、剩余持续时间、目标和效果随长局保存。

十一、推荐的程序结构
新增 scripts/life_run.gd：新长局初始化、日历、金钱、身体机能、危急和结算。
新增 scripts/life_decisions.gd：情境资格、权重、冷却、待决策、提交与延后效果。
新增 scripts/external_events.gd：暴露窗口、概率、感染预算、合法落点和一次性投放。
新增 data/life_balance.json：金额、时间换算、恢复、年龄曲线、风险、预算和边界。
新增 data/life_decisions.json：稳定情境ID、文案变体、选项、效果、前置和连锁。
新增 data/external_events.json：暴露类别、已接入病原池、器官白名单、批次与冷却。
后续新增 scripts/medicine_support.gd 与 data/medicines.json：库存、注入和助手规则。

修改 advisor_dialogue.gd / advisor_rules.gd：新增选择界面与长局人体汇报，复用现有形象。
修改 hud.gd / battle_hud.gd：金钱、身体机能、年龄与危急提示；兼容横竖屏。
修改 simulation.gd：按固定步进调用新长局模块；效果和事件不依赖 UI 的 _process。
修改 influenza_colonies.gd：为新长局显式设置初始化策略，继续复用合法流感投放与孵化。
修改 save_game.gd：验证和迁移长局状态，不破坏既有模式存档。
新增 starts/life_survival.json 或等价启动配置：复用全身地图与既有图层，单独启用 lifeRun。
第一批内部可保持 mode=fullbody 并以 lifeRun.enabled 区分；如新增独立 mode，
必须同步调整 influenza 的模式检查和相关测试，避免新模式无法开始感染。
完成闭环后再增加明确的“人体生存”入口；现有“开始作战”不在未联调前被替换。

新状态统一存入 snapshot，例如：
lifeRun: { version, enabled, elapsed, age, money, function, phase, crisisRemaining,
           runId, rulesVersion, rng, pendingDecision, nextDecisionAt,
           activeEffects, exposures, eventQueue, eventCooldowns,
           history, statistics, settledOutcome }
感染群落保留现有 colony ID；决策、暴露和入侵携带稳定的来源 ID。
历史只存有限详细条目和累计统计，不能无限增长撑爆当前 16 MiB 存档边界。

十二、随机、存档与恢复
1. 决策和外部事件使用持久化、可复现的独立随机状态，不扰动战斗已有随机序列。
   相同种子和相同操作序列应重放出相同选择与感染结果。
2. 生成待选事件时立即保存其身份、选项和已确定结果所需状态；UI 打开不重新抽取。
3. 保存尚未提交的选择、暴露剩余时间、已安排感染、延后结算、收入周期与危急倒计时。
4. 选项事务具有唯一提交ID，钱、机能和后续事件要一起生效；失败不能只扣钱。
5. 首个长局版本提供独立自动存档，建议每一主要决策结算后及每 2–3 分钟检查点保存。
   自动存档不能覆盖玩家现有手动槽位或既有系统的唯一自动槽；使用独立目录或轮换文件。
6. 先写临时文件并校验再原子替换；损坏记录不替换正在运行的有效状态。
7. 无 lifeRun 的旧存档继续原模式，不自动补跑几十次生活选择或追加感染。
   如以后提供“将当前全身存档转为长局”，采用显式入口和一次性迁移。
8. 暂时只做本地存档；不把它描述为云存档、跨设备同步或云端排行榜。

十三、分阶段实施与每批交付
阶段 A：可玩的生活决策闭环（本批已接入 40 个情境）。
   长局状态、两项数值、时间、12–16 个情境、小脑选择 UI、即时/持续效果、存读档。
   验收：点选后一次性结算，暂停/恢复正确，无钱有选项，读档保留待选择内容，既有入口可用。
   此时机能尚未自动制造正式入侵，不能宣称外部事件已经闭环。
阶段 B：机能—流感入侵闭环。
   接触标签、调度概率、右肺/已允许肺组织合法落点、活跃感染预算、风险汇报和感染负担。
   新长局接管首次感染，接入现有施工、孵化、关口扩散，避免重复刷怪。
   验收：相同暴露条件下低机能统计风险更高；不同帧率结果一致；实际出生合法、可攻击、可清除。
   与既有联合净化模块对接时，只有经验证的净化完成才关闭其绑定刷怪源，不单凭最后一个敌人消失。
阶段 C：长局寿命与可恢复性。
   年龄曲线、恢复窗口、危急、死亡结算、独立自动存档、40 个生活情境和三条连锁。
   验收：完整跨多次存档续玩，支持数小时运行；保守、均衡、透支三条路线均有明确取舍。
   长局闭环完成后提供独立正式入口。
阶段 D：多病原与多器官。
   每个病原单独完成角色、行为、素材、入口与器官白名单，再加入调度池。
   验收：复杂度来自真实不同单位和行为，混合感染有预算；无素材的角色不冒充已完成。
阶段 E：药品助手。
   钱包—购买—库存—注入—一个动态助手—实际战斗效果—退场—存档，先完整跑通一次。
   验收：付费和消费各一次，合法进入地图，确有支援行为，失效与读档一致，再扩充药品。

十四、验证与调参计划
1. 逻辑定向检查：金额/机能边界、可选性、冷却、连续透支、持续效果过期、单次提交、
   暂停、倍速、读档、独立随机、候选感染延后/取消、病原白名单、死亡只结算一次。
2. 接入回归：现有流感10–20批次、施工名额、孵化周期、拥堵、清除、关口身份和跨器官合法路径。
3. 统计检查：固定暴露与年龄下，多种种子比较高/低机能的发生率和数量分布；
   多病原接入后比较种类多样性。用足够样本验证趋势，不要求每局低机能都必然更倒霉。
4. 策略检查：以保守休整、正常工作、阶段透支、持续透支、极低余额五种策略做加速模拟。
   观察存活时长分布、破产概率、危急恢复率、入侵峰值、没有生活选择的最长间隔和事件重复率。
   希望均衡路线稳定、持续透支通常更短；保守路线更安全但资金和支援有限，不能只剩一个优势选项。
5. 加速模拟只能验证规则与统计，不能代替数小时原生运行、真实战术和用户体验验收。
6. 原生 UI 检查：小脑锚点、分句文本、选项不被提醒覆盖、按键/触控、防穿透、横竖屏、长文与结算。
7. 长时间检查：历史/队列上限、单位总量、存档体积、自动存档恢复、主线程卡顿与内存增长。
8. 实施批次按改动执行仓库要求：
   ./godot/run.sh --headless --editor --import --quit
   ./godot/run.sh --headless --script res://tests/run_tests.gd
   python3 scripts/godot_tools/audit_integrity.py
   再运行对应新模块与现有流感、存档、模式、UI 的相关测试。
9. 所有运行逻辑和资源完整保留在 godot/ 内，使用原生 GDScript、Control 和既有 CanvasItem 图层。
   不引入 Lua、Python 运行时、Maker 构建、网络依赖、远端构建、提交或推送。

十五、实施优先建议
先完成 A+B：小脑真实给选择 -> 钱/机能真实变化 -> 风险真实改变 -> 肺部出现真实感染。
这一条闭环能最早验证用户要的玩法，再补齐 C 的长局平衡和寿命，再扩 D/E。
药品价格、单场时长、起始年龄与各项具体数值，依据闭环试玩后统一校准。
本计划不表示上述系统已经完成，也不替代现有全量玩法、画面、云存档或手机验收边界。
