# 器官阻挡节点编辑器

本地入口：http://127.0.0.1:56946/obstacles/

编辑器读取游戏当前 `OrganBattlefield` 返回的 12 个器官轮廓及对应注册底图。图层包括 `styledObstacleRings`（道具底座）、`wallRings`（围墙）与 `outerRings`（器官外边界），保留孔洞。界面节点经过轻微简化以便操作；未编辑的轮廓保存时使用原坐标，而非界面节点的简化版本。

用户可切换器官、拖动节点、双击边线插点、删除节点、新增闭合轮廓、在选中轮廓中新增孔洞、撤销/重做、输入坐标微调、填写备注并标记器官已确认。滚轮缩放，空格拖动平移；“放大选中”适合精修，“适合窗口”查看全器官。

## 保存与后续读取

- `current.json`：最近一次“确定保存 → 确认保存到项目”的完整结果。
- `history/`：每次确认保存的历史版本。
- 浏览器本机草稿用于意外刷新恢复；草稿不等同于确认保存。
- `current.json.organs` 是用于后续审核/接入的源坐标多边形，包含 `obstacleRings`、`wallRings`、`outerRings`、备注及确认状态。
- `editorDocument` 是继续打开编辑时的节点状态。
- `sourceArt` 和 `baselineRevision` 可核对底图版本。`runtimeApplied=false` 表示尚未接入游戏运行数据。
- 用户说“调整好了，查看保存结果”时，先读取 current.json 的版本、器官确认状态和变更摘要，再渲染对应轮廓与注册底图核对。不要仅修改 JSON 后宣称游戏阻挡已改变；正式接入仍需重建对应可行走域与半径相关导航数据，保持层级、端口和通路规则。

原心脏 `walls-0` 已有一处复杂交叉结构；保存器会允许该已有结构并在输出保留 `reviewWarning`，接入前必须复核。其他新出现的自相交、越界孔洞、非有限坐标会阻止确认保存，浏览器草稿仍保留。

## 2026-10-19：粗框 / 粗圈自动贴边

「框选贴边」拖一个矩形框；「圈选贴边」画大致包围圈。松开后从注册底图在本机提取外缘，灰色虚线保留圈选范围，紫线预览识别结果；可放大预览、撤销/重做，检查后「确认轮廓」。继续调整原有阻挡时，先选中旧轮廓，再使用「贴边重画选中」，确认后替换该外圈或孔洞；普通框选用于新增。

框住单个物体或相连的一组凸起物，四周留一点地面。多块不相连的物体只预览最大的一块，其余分别框选。算法使用外缘，不把物体内部绘制的细胞核/高光挖成可通行洞。若结果碰到圈选边缘过多，提示物体未框全；交叉圈选与不稳定结果被拒绝。色差不明显的地方仍需手绘修正，预览必须经用户确认。

程序新增 `contour_trace.py`，本机 OpenCV GrabCut + 外轮廓提取；依赖安装于 `.tmp/vascular-refinement-python`（opencv-python-headless 4.11.0.86，沿用 NumPy/Pillow/CairoSVG）。`POST /api/trace` 仅返回预览，不保存项目。沿用本地 Host/Origin/请求头校验。服务只在 127.0.0.1 监听。

验证：实际拖框得到肺部四叶凸起物的 32 节点外缘；笔画撤销/重做后预览一致，确认后增加 1 轮廓，整体撤销后所有图层路径与用户草稿完全一致。HTTP 验证了成功提取、未框完整拒绝、自交圈选拒绝。未产生测试保存；项目保存版本仍为 1。手绘/框选过程中提示区固定高度，避免文字换行推动画布、导致笔画坐标偏移。
