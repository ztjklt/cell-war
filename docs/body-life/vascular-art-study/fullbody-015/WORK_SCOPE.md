# 全身 0.15 战场工作范围与验收合同

本轮目标是完成真实游戏倍率 `zoom=0.15` 下的全身战场。工作必须连续推进到全身合成、跨区域通行、原生复核和正式地图接入，不能再次以胃部试样完成代替全身完成。已有胃、11 个器官和胃血管试样作为可复用基准保留。

`contract.json` 是完整范围、坐标权威和初始覆盖状态的持久化记录；它不是一份“全身已完成”的证明。`scripts/qa/audit_fullbody_015_contract.py` 的默认执行为只读，成功状态特意称作 `PASS_FROZEN_INVENTORY_ONLY`。使用 `--require-complete` 时，任何缺少验收的全身阶段都会令检查失败。

## 不可被生图或局部工作改写的条件

- 脑部与四肢已认可的血管位置、姿势和外轮廓保持固定；本轮不重新设计其路线。
- 全部定稿边的端点、连接关系、宽度、控制点和曲线以冻结数据为准。GPT 提供画面材质与接头原料，像素不决定碰撞或寻路。
- 胃和肝允许符合器官设定的少量绿色；其他器官和所有血管地形不能加入绿色。细胞阵营、选择标记和 HUD 与地形颜色区分检查。
- 食道、胃腔、十二指肠、肺内支气管、尿路和胰管不能改成血管，也不能因此成为细胞入口。
- 投影交叉不自动形成分叉；供给/回流口与细胞进入组织的膜口分别定义。
- 保留现有器官轮廓、房间、真实组织门和外侧隐形碰撞墙。开放地面保持平坦、低对比，不能用密集装饰或凸起阻碍 RTS 阅读。
- 不迁移旧存档位置；旧人体版本、原有地图和已存在的战役继续走其原路径。本轮没有提交、推送或远端发布。

## 连续实施与验收顺序

1. **全身骨架和可通行平面**：对全部 202 条边、19 个 region、全部供回流接口及 18 个显式器官口逐一建立覆盖表。检查命名节点端点完全相接、上下层交叉正确、食气尿路独立。确定 0.15 下深层主干如何显示及其单位如何被识别，不能把“隐藏”误认成断路。
2. **大主干与分支材质**：先覆盖全身主干，再覆盖到各器官、头部和四肢的分支。按统一颜色、轮廓和材质尺度映射 GPT 素材；共享长段可以复用，全部定稿曲线保持不变。
3. **GPT 接头与组织入口**：在命名分叉、粗细交接、供回流口和组织膜口制作局部接头素材。冻结曲线决定接头最终位置和开口形状；不可用一层渐隐当作已完成连接。
4. **完整全身合成**：大血管、分支、12 器官和器官间地面在同一渲染链合成。逐区域检查背景、前景、组织墙、保护腔和血管管腔；所有旧粗填色的保留/替换范围明确。0.085→0.15 连续交接，不出现双地面、错位、透明黑边或关闭的门。
5. **真实跨区域通行**：使用 production Commands、Path、CellCollision 和交通模块；每个器官都测试“主干→供给分支→膜口→组织房间→出口→另一个 region”。scout/siege 均覆盖，检查转弯、出口净空、排队、会车、集结、反向和取消命令。不能从局部安全区域的单单位测试推出全身拥挤通行通过。
6. **原生与正式地图**：在真正 0.15 相机下逐区域连续浏览并移动细胞，覆盖世界和地图弹窗的不同投影、DPR 1/2/3、桌面/平板/手机横竖屏。采集连续移动/缩放、资源生命周期和同机开关 P95 对比，再完成新独立全身地图的菜单入口、初始化、保存、恢复及双 context 验收；旧地图和旧战役按原路径回归检查。

完成条件是这条链闭合。允许阶段内并行生成和验证，不要求每个小步骤后等待用户再次说“继续”；发现需要用户决定的实际范围变更时，先保存可复核事实。

## 编译器接口

读取 `contract.edges[]`，按 `geometryRef.path` 和 `geometryRef.edgeId` 在原始定稿文件中取得完整 `samples`。合同内提供 `a/b`、控制点、SVG `d`、宽度、layer、完整几何哈希及 samples 哈希。

`registered-vessels/geometry.json` 是腹胸部 ROI 的 80 条画面片段，不能用它代表 202 条全身路线。保护边的位置不改，但不能因它们未进入旧 ROI 而遗漏全身材质和实际 0.15 验收。原图概览的 `hiddenIntervals` 与 0.15 战场的切面显示需要分别记录；任何新的显示策略不得变更血管的实际连接关系。

每条边至少记录：冻结参考、GPT 映射、接头美术、全身合成、生产运行、跨区域移动、原生验收、正式地图接入（`formalMap`）。可以将经验证确实应隐藏的显示片段记为 `INTENTIONALLY_OCCLUDED_VERIFIED`，但必须绑定遮挡依据及当前资源/代码证据，不能把无素材、无接续或未经检查的缺失记作遮挡。验收记录的 evidence 使用 `{path,sha256}`，仅填 PASS 文本不能替代当前文件证据。

## 正式运行接入的约束

基线 `OrganBattlefield.enable` 拒绝 campaign；`Save.restore` 同样拒绝在 campaign 中恢复器官试验标记；`VascularMaterialArt.enabled` 也明确排除 campaign。只修改绘制入口、或把试验按钮称作正式地图，不能满足接入要求。

本批已确定采用**新的独立全身可玩地图模式**：`fullbodyBattlefieldVersion=1` 显式 opt-in，覆盖 12 器官及全身 202 条血管，由菜单直接进入。步进复用 OrganTrial 已接通的 production Commands、Path、Workers、Collision。正式接入指这一完整可玩地图入口，不包含把现有气管战役扩展成全身关卡。

存档保存新的可选地图标记，不提高全局存档版本；没有标记的旧 campaign、普通 sandbox、器官试验存档及其路图保持原样。必须成套核对新入口、World.generate、Save.snapshot/restore、Simulation、Commands/Path/CellCollision 和 Vessels.forState。不要为接入新地图而删除旧 campaign 的保护判断，也不能自动向旧存档注入新标记或迁移单位位置。

外围组织策略也已确定：本批不扩充 `arm_r/arm_l/leg_r/leg_l/trunk` 五个组织域，这些区域沿全身血管通行；血管外地面明确不可行走。现有 OrganTrial 的 lane0 只允许 12 器官域，不能把全身血管贴图覆盖解释成四肢/躯干的血管外地面自动可走。合同保留这五个 region 的接口，并将其通行策略单独验收。

## 证据规则

所有生成原料、编译图、覆盖表、移动结果和原生截图必须绑定当前输入、资源和代码 SHA。离线渲染可证明注册和逻辑结果，不能代替原生过滤接缝、实际连续移动或 GPU P95。素材重新生成后不得沿用旧截图作为新验收证据。

原生预览按项目规则查询状态；会话存活则刷新并读取日志，停止的会话不得自行重启。当前已知 `Cube/Day/DaySpecularHDR_QualityLow.dds` 缺失另列基线，不能把它隐去后宣称本地 CLI 全通过。缺少证据的项目标记未确认，保持工作范围和剩余量可见。
