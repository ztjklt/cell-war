## 验证环境

- macOS，本机官方 Maker CLI 0.0.36 与已安装的 UrhoXRuntime。
- 正式入口 `scripts/main.lua`，Maker Lua 5.4、NanoVG 世界绘制与 `urhox-libs/UI` 原生界面。

- 桌面操作通过原生预览窗口实测；触屏规则通过指针回调测试。没有手机真机数据。

## 原生 Maker 预览

已观察主菜单、原创手绘世界、八项库存、人口、昼夜时钟、选中面板、建造卡片和小地图。实测选择工人、暂停放置仓库、恢复后扣费施工、工人到达并完成建筑。暂停期间时钟和单位饱食不变化，界面按钮点击不会发出世界移动命令。

实测打开存档面板并尝试保存：本地未连接 `clientCloud` 时明确提示失败，当前游戏仍可继续，没有错误显示“已保存”。真实云成功与跨会话读取没有验收。

使用隔离的 `Acceptance.stress()` 满人口夹具，在原生窗口观察三个阵营共 120 个单位，HUD 显示约 60 FPS。夹具只用于性能预览，已从正式入口移除。此结果是桌面窗口瞬时观测，不能替代手机最低帧率或长时间渲染性能结论。

原生自动化的拖动事件被合并，无法据此确认真实连续拖动的表现。鼠标框选和触屏拖镜头的逻辑测试已通过，仍需真人设备确认手感、双指缩放及安全区。

## 两轮四季运行

初版 v1 代码完成 64 天、两轮秋冬春夏，种子为 `1`。使用真实 0.1 秒固定步进、同一个世界、正常资源和生存消耗。玩家由测试驱动执行发展与近营防守；两敌方 AI 保持正式决策，允许正常战斗、撤退及阵营覆灭。测试没有重置世界、赠送资源或绕过失败。原始结果见 [soak-results.json](soak-results.json)。

| 指标 | 结果 |
| --- | --- |
| 模拟时长 | 23,040 秒，230,400 个固定步进 |
| 状态 | 继续沙盒，未触发玩家失败 |
| 每日采样最大实体数 | 150（包含单位、建筑与野生实体） |
| 每日采样最大待处理寻路数 | 20 |

逐日检查各阵营实际人口和容量均不超过 40，实体坐标与生命没有出现非数值。第二轮季节的内存峰值没有继续增加；此检查只覆盖 Lua 管理内存，未测引擎、纹理或 GPU 长期占用。

结束时玩家 T3、40 人口；两个 AI 分别 T2 与 T1，均损失全部单位但仍有生产建筑，因此尚未满足征服条件。测试覆盖 AI 发展、探索和作战，但单一种子与测试指挥策略不能代表所有随机世界的难度平衡，也不保证每个阵营都能存活 64 天。

## 运行包与剩余验收

当前官方本地运行包报 `Could not find resource Cube/Day/DaySpecularHDR_QualityLow.dds`，CLI 因此返回 `ready:false`。游戏日志随后出现 `[Render] graphics ready` 和 `[荒野战争] READY`，原生窗口实测可玩；不能把进程存活或 CLI 状态当作全量验收通过。还有默认下载资源与项目记录提示；本次没有修改官方引擎文件。

资源准备器还把 HUD 一段界面文字误识别为图片路径。游戏使用的原创图片与音效已进入本地资源包，原生窗口实际显示精灵。

以下需相应设备或服务环境完成：手机横屏与刘海安全区、真机双指及 30 FPS、云服务真实跨会话读写和刷新后恢复、长时间原生渲染及引擎整体内存。远端代码提交和构建按用户边界尚未执行。

```lua
assert(regression.passed == regression.total)
local longRun = QA.soak(64, 1)
```
