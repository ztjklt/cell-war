# 心脏四腔战场重建计划

日期：2026年10月12日。状态：四腔玩法、项目既有血管图片与持续心跳已接入，正常入口已恢复。原生通行/战斗 8/8，最终四腔战斗/隔墙复核 2/2 通过。桌面 P95 帧时增幅约 0.3%；扩展的严格 CPU 5% 指标仍未达标，手机验收尚未进行。

目标是把当前心肌组织地图重建为两心房、两心室清晰可辨且都能进入战斗的心脏剖面战场。最终美术使用 GPT 生成素材；心脏有自然的收缩、舒张动态；心脏与旁边四条粗血管在静止、心跳及缩放过程中均连续融合。

用户已确定四腔均可进入战斗，以及保留当前四条粗主干的外部位置。局部结构设计采用解剖关系明确、便于俯视操作的平面剖面，沿用现有柔和手绘有机卡通风格。当前图中的四条粗干需要在第一步逐条标定，不能直接把画面中的四条管道等同于四类解剖血管。

## 改造前基线与范围

现行心脏使用 `assets/image/anatomy-reference/vascular-study/fullbody-015-candidate-v4b/organs/heart.png`，源坐标框为 `[468,326,568,467]`，贴图为 `1200×1692`。世界映射为 `(sourceX*2, sourceY*2+512)`。

当前三个内部开放湾是心肌组织分区，[原说明](body-life/vascular-art-study/organ-atlas/revision-v2/README.md)明确它们不代表解剖心腔。运行时血管采用 `FinalVascularStudyData`，已具备左右肺循环，但心脏只用左心、右心和入心静脉汇点表示。此次需要建立四个独立血液腔室、隔墙和四个瓣膜口，并更新相关寻路与战斗规则。

旧 `BodyLife` 心脏形变在倍率达到 `0.15` 时停止，近景心脏由静态全身贴图绘制。新动态必须接入实际近景心脏层，并重新定义心脏和血管根部的形变范围。

本计划将心脏局部合同升级为四腔结构。外部四条粗干的锁定截面、肺门接口以及全身其余路线继续作为对接基准。局部重建包含旧左心、右心抽象节点的拆分、瓣膜口、冠脉回流接入和必要的近端血管适配。

## 四腔结构和通行

建立右心房、右心室、左心房、左心室四个独立腔室。通过真实形状、肌壁、中隔和瓣膜口形成可识别关系，腔室内部使用宽阔、低对比的血液空间，心肌组织、冠脉和四个心腔具有明确边界。

基本连接为：腔静脉回流 → 右心房 → 三尖瓣 → 右心室 → 肺动脉瓣 → 肺动脉 → 双肺 → 肺静脉 → 左心房 → 二尖瓣 → 左心室 → 主动脉瓣 → 主动脉。左右心之间由中隔分开；冠脉属于供养心肌的独立循环，回流接入右心房。这些解剖关系以 [NHLBI 心脏血流说明](https://www.nhlbi.nih.gov/health/heart/blood-flow)为依据。

现有路线的局部适配如下，最终以第一阶段接口图复核后的候选数据为准：

| 现有连接 | 四腔方案 |
| --- | --- |
| 入心静脉汇点 `heart.v` 与旧右心节点 | 汇入右心房，右心房和右心室之间建立三尖瓣口 |
| `e002` 旧右心通向肺动脉干 | 从右心室经肺动脉瓣进入原肺动脉干 |
| `e005/e008` 双肺回流通向旧左心 | 接入左心房，经二尖瓣口进入左心室 |
| `e150` 旧左心通向主动脉根 | 从左心室经主动脉瓣进入原主动脉根 |
| `e146` 冠脉回流通向旧右心 | 接入右心房 |

四腔使用独立 `chamberId` 和血液空间数据，复用现有整圆、扫掠碰撞和通行调度能力。瓣膜口与组织膜口使用不同身份；四个心腔不合并成统一心肌地面。

首版通行建议采用稳定的开放入口，细胞可按命令在腔室内移动与战斗；血流视觉遵循生理方向。瓣叶小幅摆动时保留明确的可通过空间。若后续需要瓣膜完全闭合并阻挡单位，另行接入开闭状态、等待和重新寻路，使显示和通行同步。

实际战斗复用现有单位与攻击系统，同时补足全身地图的隔墙视线检查。验收包含同腔攻击、跨腔追击、瓣口会车、不同阵营交战、单位死亡和特效清理。左右心隔墙不能被攻击或寻路绕过。

## GPT 美术和图层

先将现有心脏、四条粗干、附近肺部和气管的实际合成画面作为上下文，制作包含四腔、血管根部和锁定接口的整体结构导图。GPT 在这一范围内完成统一整体稿，随后基于同一稿与导图制作分层素材。

| 素材内容 | 用途和要求 |
| --- | --- |
| 四腔血液底层 | 保留可战斗空间，色差柔和，避免肌肉纹理铺满腔室 |
| 心肌与中隔 | 清楚建立四腔轮廓，墙体位置与结构数据一致 |
| 瓣膜细节 | 四个对应入口可辨认，材质属于心脏，形态适合轻微动画 |
| 四条粗干近端和根部接头 | 连续生成或局部编辑，管壁、管腔、色调和光照统一 |
| 局部遮挡和融合边带 | 恢复应在上层的心壁或气管，保持完整的血管出入口 |

最终表面保留柔和组织纹理，降低腔内地面和高光的对比，给细胞、选择标记和战斗效果留出阅读空间。产品素材不烘焙单位、文字、选择圈或 HUD。保留当前红粉与蓝紫血管风格；肺循环颜色按含氧状态复核，不能机械地把所有动脉画红、所有静脉画蓝。

GPT 生成结果逐张检查四腔形状、入口、透明度、材质和风格。模型输出需要按导图配准及几何裁切，局部漂移通过定向编辑修正；生成图中的装饰线不能自动变成碰撞墙。

当前全身合成顺序为 `surfaceTiles → organs → deepTiles → junctions → foregroundPatches`。心脏方案必须一起交付现有 `arch-roof-and-junction`、`heart-venous-junction` 及相关血管层的替换范围，避免旧顶盖、旧管口或静态心脏残层遮住新结构。气管前景继续按实际遮挡关系接续。

## 心跳时如何保持四条血管融合

采用心房先收缩、心室随后收缩并舒张回弹的节奏。动态由新心脏素材的局部形变和柔和明暗变化产生，不移动相机。初始形变幅度以约百分之一至百分之二作为调试起点，最后按真实画面和通行余量确定。

四条粗干远端锁定的是完整横截面，包括两侧管壁、管腔和切线方向。靠近心脏的短段与心肌使用同一形变，过渡带将位移与斜率平滑衰减到零。整张心脏 PNG 的独立平移、缩放无法保证这些接口连续，因此不作为最终动画方案。

共享形变网格覆盖腔底、心肌墙、瓣膜、近端血管和遮罩。细胞先取得原有移动插值位置，再映射到同一显示网格；选择圈、血条、血流、攻击特效和命令标记使用同一帧相位。点击与地面指令通过同一网格的反向映射落回逻辑坐标，相机缩放仍使用原有视图坐标。

首版逻辑碰撞采用固定几何，通过统一显示变换保持墙和单位的画面关系稳定。最大收缩时必须仍有足够边界余量，网格不能翻折，单位足迹不能露出墙外。心跳挤压或推动单位属于额外玩法，只有需要时才接入真实动态碰撞。

全身总览和战斗近景都应保留心跳。跨越 `0.085 → 0.15` 时使用同一结构和节奏过渡，避免四腔突然出现、结构重影或到战斗倍率停止跳动。

## 与当前地图 Agent 的接入边界

当前「地图生成」聊天仍负责全身材质接头、原生复核和性能检查。心脏工作先产出独立版本的素材、逻辑候选和接口记录，例如 `assets/image/heart-v1/` 与 `docs/heart-v1/`；新模块可按职责拆为 `HeartBattlefield`、`HeartArt`、`HeartMotion` 和 `HeartDisplayTransform`。

共享全身编译器、最终资源清单、`FullBodyMapArtData.lua` 和前景合同由单一集成负责人在明确基线后导入。交接包包含接口表、编辑范围、图层遮挡顺序、素材来源、候选数据和验证结果。准备交接后再同步给对方，保证其正在修改的血管和气管图层与心脏候选使用相同接口。

旧全身编译流程默认保留已接受器官地面。新四腔应以新的心脏合同导入，不能作为普通补图重跑旧生成器。旧通行报告继续说明原版本；新四腔和受影响的肺循环、冠脉、入出心接头需要新的实际验证。

当前全身纹理已达到每 context 四十二项资源上限，解码 RGBA 约二百五十三 MiB，上限二百八十八 MiB。心脏分层优先打包进替换现有资源的专用纹理图集，通过子区域与有限网格绘制动画；实际图集尺寸以资源预算复核结果确定。资源验证同时考虑世界与地图弹窗的两个 context，以及 mipmap 和运行时峰值。
